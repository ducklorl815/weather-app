# Little Reply phase 1: Reply Pop modularization + event/toast unification

We are optimizing Little Reply for UX first, but the Reply Pop monolith and dual cache-list events / dual Toast dedupe block safe changes to live refresh, focus, and send. Phase 1 therefore does structural work first (split `gchat-reply-pop` into a small component set under `renderer/components/gchat-reply-pop/` sized to unlock UX work—not a deep widget tree; make `gchat-cache-changed` the only Cache Push and drop `gchat-list-updated` as a live semantic event; Main-only Toast Dedupe Owner), then UX on the Reply Pop main path (open-window-sensitive live update, entry-based focus, Failed Optimistic Reply with retry). We rejected “UX-only edits inside the 4k-line HTML” and “defer Main event/toast cleanup to a later maintainability pass” because both would force a second rewrite of the same surfaces.
