# Scope Registry + Little Reply core/extended tiers

Repeated Feature Scope Gates (especially Little Reply) come from parallel scope checks (`FEATURE_SCOPE_MAP` vs looser helpers like `hasChatScopes`). We make Scope Registry (`FEATURE_SCOPE_MAP` and its helpers) the only source of truth for gates, asserts, and sync, and split Little Reply into Core Scopes (Inbox / Reply Pop main path) vs Extended Scopes (directory / contacts / custom emoji, etc.) so extended gaps use Incremental Auth instead of blocking the whole surface. Full Login still requests the full application scope set when possible. We rejected keeping dual track lists and collapsing everything to the minimal `hasChatScopes` set as the product default, because the former keeps “authorize again” loops and the latter fights the Full Login policy.
